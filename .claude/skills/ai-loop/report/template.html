Build with AI Loop

I tested Build with AI the way a person uses it. I typed a request into the dialog, copied the prompt it makes, gave that to a separate AI, pasted its answer back and looked at the world. After each round I fixed what went wrong and ran the same request again. Then I tested asking for changes to a world the same way.

RequestWhat the person types into “What should your AI build?” or “What should it change?”. Written by an agent that knew only what the home page says. Shown in blue for changes.
PromptWhat the app copies when they click Copy the prompt: their request plus the guide, every part, an example world, and for a change the world itself. 30 to 50 KB.
AIA fresh agent that saw only the prompt. Either a plain chat AI with no tools, or one that could also read the format online and check its answer with validate.
ResultThe answer pasted back into the dialog and opened, with pictures in View mode and what validate says about it today.

The fixes

Fix 1

Validate names fields that don't exist

A made-up field like lighting.timeOfDay was dropped silently, and the dialog still said “Ready to open”. Now it's a warning that lists the fields that place does have.

src/parts/validateWorld.ts

Fix 2

Validate says when a size is out of range

“0.04 isn't a width box_01 takes (at least 0.05): it's drawn with 1”, where it used to say nothing.

src/parts/validateWorld.ts

Fix 3

Validate finds things buried in a hill

It gives the altitude to use instead. A little way into a slope, as Stockholm's buildings stand, isn't warned about.

src/parts/validateWorld.ts

Fix 4

Validate checks colour names on the ground, roads and areas

ground.colors.ground did nothing; the warning now says the ground's colour is called surface.

src/parts/validateWorld.ts

Fix 5

Units with a space: “103.4K kWh”

The format's description told AIs to write units like "km/h", but the app shows a unit exactly as typed. The description now says to put a space before a word, and validate warns when one is missing.

src/scene/schema.ts · validateWorld.ts

Fix 6

The “stands inside” warning gives heights

It now ends with how high each object reaches (“the warehouse reaches up to 3.4”), so an AI can stand panels on a roof without dozens of guesses.

src/parts/validateWorld.ts

Fix 7

The guide teaches the basics an AI was guessing

Where things are ([x, z]; a point's height is its third number), which way turning goes, time of day and weather with the hours of dusk, what a running clock does, colour names, hills with peaks and standing things on them, size limits, and showing many cards as small chips.

src/guide/guide.ts (in every prompt, and /guide.md)

Fix 8

The AI may add a note after its answer

For a new world and for a change: what it built from shapes, what it couldn't do, numbers it assumed. The dialog still reads only the JSON.

src/editor/aiPrompt.ts

Fix 9

A change takes what's selected along

The prompt lists the selected things by id and name. The dialog's hint says so: “Select things in the world first to say ‘this’ or ‘these’”.

src/ui/BuildWithAiDialog.tsx · aiPrompt.ts · guide.ts · e2e test

Fix 10

A change's summary reads at a glance

“adds Ski, Ski, Skier, Skier's head, Ski…” became “adds Ski ×8, Skier ×4, … and 11 more”.

src/scene/worldPatch.ts

Checked with pnpm check, pnpm typecheck, all 2,161 unit tests, and the Build with AI and sharing end-to-end tests plus a new one for the selection. Every starter world still validates with no warnings.
